## 1. О проекте в двух словах

Репозиторий **`dca_bot`** представляет собой готовую алгоритмическую систему для торговли бессрочными фьючерсами Bybit (**Linear USDT Perpetuals**) на базе стратегии **«Манипуляция на часе» (1H Fibonacci Price Action & Dual Grid)**.

Система включает в себя:
1. **Боевой торговый бот Bybit V5** (`scripts/bybit_trader.py` + `indicators/pybit_client.py`) с поддержкой мульти-монетного трейдинга, параллельной двухуровневой торговли (Minor $\le 24$ баров и Major $25..96$ баров с экономией маржи до 0.382), авто-трейлинга сеток, защиты по SL/БУ, контроля остаточного риска (Residual Risk Budget) и подхвата ордеров при перезапуске через биржевой `orderLinkId`.
2. **Индикатор TradingView** (`indicators/fib_dual_grid.pine`) — визуальное отображение импульсов, сеток, свипов и сигналов.
3. **Интерактивный бэктестер и симулятор** (`scripts/backtest_strategy_interactive.py`, `scripts/backtest_manipulation_grid.py`).
4. **Модуль анализа волатильности и DCA** (`volatility_calc/`).
5. **Набор автоматических тестов** (`tests/test_bybit_trader.py`, `tests/test_risk_guard.py`, 175 тестов).

## 3. Логика торговой стратегии: Три ключевых варианта

Стратегия работает на таймфрейме **1H** в направлении **LONG**.

### 3.0. Построение импульса
* **Старт ($L$):** `low` первой свечи импульса.
* **Вершина ($H$):** Абсолютный максимум волны по теням (`high`), вне зависимости от цвета свечи.
* **Минимальный импульс:** $\ge 2.0\%$ `(H - L) / L * 100%`.
* **Шкала Fib:** Логарифмическая: $\text{Price}(\text{level}) = \exp(\ln(H) - \text{level} \times (\ln(H) - \ln(L)))$.
* **Уровни:** $0.000 = H$, $1.000 = L$ (стоп сетки).

---

### ВАРИАНТ 1: Ложный пробой (Sweep Reclaim + MACD + Безубыток)
Сценарий краткосрочного снятия ликвидности за уровнем $1.000$:
1. **Условия:**
   * Тень свечи пробивает уровень $1.000$ не глубже чем на **0.5%** (`reclaim_max_sweep_pct: 0.5`).
   * **Ни одна свеча не закрывается телом ниже 1.000** (`reclaim_allow_close_below: false`).
   * **MACD Rebound:** Гистограмма MACD на свипе или реклейме показывает разворот вверх ($\text{Hist}[k] > \text{Hist}[k+1]$ или $\text{Hist}[0] > 0$).
2. **Вход:** На возврате цены выше уровня **1.000 Fib** (Reclaim).
3. **Стоп-Лосс:** Чуть ниже абсолютного минимума тени свипа (`SweepLow * 0.9995`).
4. **Тейк-Профит:** Уровень **0.618 Fib МИНУС 2.0%** (`Price(0.618) * 0.98`).
5. **Безубыток:** При росте цены до уровня **0.786 Fib** стоп-лосс автоматически переносится в безубыток: $\text{Вход} \times 1.0005$ (+0.05% на покрытие комиссий).

---

### ВАРИАНТ 2: Тройная сетка коррекции (Triple Grid) с Трейлингом и каскадным TP
Классическая коррекционная сетка внутри импульса (без пробоя 1.000):
1. **Ордер 1:** Уровень **0.500 Fib** $+0.07\%$ буфер входа. Тейк: **0.236 Fib** $-0.10\%$ буфер. При закрытии по TP ордера 2 и 3 отменяются.
2. **Ордер 2:** Уровень **0.618 Fib** $+0.07\%$ буфер входа. При наливе цель всей позиции снижается до **0.382 Fib** $-0.10\%$ буфер. Ордер 3 остается в стакане. При закрытии по TP Ордер 3 снимается.
3. **Ордер 3:** Уровень **0.786 Fib** $+0.07\%$ буфер входа. При глубоком сквизе до 0.786 цель для ВСЕХ трех ордеров снижается до **0.500 Fib** $-0.10\%$ буфер! Ордер 3 дает сверхприбыль, Ордер 2 закрывается в плюс, Ордер 1 выходит в безубыток.
4. **Стоп-Лосс:** Ровно на уровне **1.000 Fib**.
5. **Распределение объема входа и риска:** Объем позиции распределяется в пропорции **50% / 30% / 20%**:
   * **Ордер 1 (0.500):** 50% от совокупного номинала позиции ($\text{Notional}_1 = 0.50 \times N$).
   * **Ордер 2 (0.618):** 30% от совокупного номинала позиции ($\text{Notional}_2 = 0.30 \times N$).
   * **Ордер 3 (0.786):** 20% от совокупного номинала позиции ($\text{Notional}_3 = 0.20 \times N$).
   * При этом совокупный номинал $N$ рассчитывается так, чтобы суммарный риск при одновременном выбивании всех трех ордеров по SL 1.000 был строго равен лимиту из конфига ($\text{Loss}_1 + \text{Loss}_2 + \text{Loss}_3 = \$2.00$).
6. **Трейлинг:** Если цена обновляет вершину $H$ без отката к 0.500, бот пересчитывает уровни и сдвигает все три ордера выше через `amend_order`.
7. **Отмена ордеров:** При выбивании по SL или закрытии позиции оставшиеся незаполненные лимитные ордера немедленно снимаются.

---

### ВАРИАНТ 3: Сетка манипуляции (1.414 & 1.618 — 100% Win Rate)
Сценарий глубокого пробоя импульса (манипуляция и вынос стопов):
1. **Условия:** Выход цены за $1.000$ глубже **0.5%** ИЛИ закрытие часовой свечи телом ниже $1.000$ (при отсутствии отскока с дивергенцией MACD).
2. **Ордер 1:** Уровень **1.414 Fib** $+0.10\%$ буфер $\to$ одиночный TP на уровне **1.000 Fib** $-0.10\%$.
3. **Ордер 2 (DCA):** Уровень **1.618 Fib** $+0.10\%$ буфер $\to$ при наливе Ордера 2 общий TP всей корзины переносится на **1.414 Fib** $-0.10\%$ (Ордер 1 в безубыток, Ордер 2 в прибыль).
4. **Стоп-Лосс:** Уровень **2.414 Fib** (суммарный риск распределяется поровну по \$2 на ордер).
5. **Результат бэктеста на дампах (SUI + NEAR):** 16 TP из 16 дампов (**100% Win Rate**).

## 4. Особенности интеграции Bybit V5 Linear (Критично для кода)

При модификации торгового кода строго соблюдайте следующие правила Bybit API:

### 4.1. Категория и формат символов
* Торговля ведется в категории **`category="linear"`** (USDT Perpetuals).
* Символы TradingView с суффиксами `.P` или `.PERP` (например, `NEARUSDT.P`, `ZECUSDT.P`) **обязательно форматируются** через функцию `format_symbol()` $\to$ `NEARUSDT`, `ZECUSDT`.

### 4.2. Режим позиций: Hedge Mode vs One-Way Mode
* На Bybit Unified аккаунтах часто включен **Hedge Mode (Dual-Side Position)**.
* В Hedge Mode:
  * Для Long (Buy): **обязательно** передавать **`positionIdx: 1`**.
  * Для Short (Sell): **обязательно** передавать **`positionIdx: 2`**.
* В One-Way Mode: передается **`positionIdx: 0`**.
* Метод `client.get_position_idx(symbol, side)` в `indicators/pybit_client.py` **автоматически кэширует и подставляет нужный `positionIdx`**, предотвращая ошибку Bybit `10001 (position idx not match position mode)`.

### 4.3. Авто-подхват существующих ордеров и защита от дублирования (Order Adoption & Deduplication)
* **Биржевые `orderLinkId` с префиксами слоев:** Каждый ордер сетки получает уникальный детерминированный идентификатор `FIB-{SYMBOL}-{LAYER}-{SIDE}-O1` (O2, O3), где `LAYER` равен `MIN` (Minor, $\le 24$ баров) или `MAJ` (Major, $25..96$ баров). Bybit на уровне биржевого движка гарантирует уникальность `orderLinkId` и отклоняет любые попытки дублирования ордеров.
* **Изоляция отмены ордеров (`cancel_monitor_orders`):** Отмена ордеров при закрытии сделки или выбивании по стопу выполняется строго в рамках своего слоя (`MIN` или `MAJ`). Закрытие локальной сетки Minor никогда не отменяет лимитки или доборы старшей сетки Major.
* **Бюджет остаточного риска (Residual Risk):** Перед созданием ордеров бот запрашивает фактический объем позиции. Если позиция уже открыта (`pos_size > 0`):
  - Вычисляется текущий задействованный риск: $\text{CurrentRisk} = \text{size} \times |\text{avgPrice} - \text{SL}|$.
  - Если $\text{CurrentRisk} \ge \text{setup\_risk}$ ($2.00) — создание любых новых ордеров блокируется, лишние лимитки своего слоя снимаются.
  - Если $\text{CurrentRisk} < \text{setup\_risk}$ — объем оставшихся ордеров рассчитывается строго из остатка ($\text{RemainingRisk} = \text{setup\_risk} - \text{CurrentRisk}$).
* **Режим Close-Only:** Если на аккаунте найдена открытая позиция по монете, которой нет в активном списке торговли (`symbols`), бот автоматически берет её на сопровождение в режиме `Close-Only` (доводит до TP/SL, после чего завершает мониторинг без открытия новых сделок).
* **Устойчивость к сетевым сбоям:** В клиенте Bybit включен автоматический перезапуск упавших соединений (`force_retry=True`, `max_retries=10`, `retry_delay=3s`, `timeout=20s`), предотвращающий прерывание цикла мониторинга при `ConnectionResetError` или тайм-аутах DNS.

### 4.5. Конечный автомат (State Machine) жизненного цикла сделки
Бот отслеживает полный жизненный цикл сделки через функцию `process_monitor_step()`:
1. **`AWAITING_MAJOR_0382`**: для Большой фибы ($25..96$ свечей), если текущая цена выше $0.382$. Лимитные ордера на биржу **не выставляются** (маржа свободна для мелких входов). Монитор трейлит вершину, пересчитывает $0.382$. При касании или пробое $0.382$ ($low \le p_{0.382}$) выставляется тройная сетка `MAJ` и монитор переходит в `TRAILING`.
2. **`TRAILING`**: ордера 0.500, 0.618 и 0.786 выставлены на биржу; при обновлении вершины импульса уровни сдвигаются выше через `amend_order`.
3. **`O1_FILLED`**: налит Ордер 1 (0.500), TP позиции стоит на 0.236 Fib. Если цена разворачивается и берет TP 0.236 — бот немедленно снимает висящие Ордера 2 и 3 своего слоя (`cancel_monitor_orders`) и переходит в `IDLE`.
4. **`O2_FILLED`**: при проливе налился Ордер 2 (0.618) — бот автоматически вызывает `client.set_position_tp_sl()` и переносит Take-Profit всей совокупной позиции на общий уровень **0.382 Fib**. Ордер 3 активен в стакане. При взятии TP 0.382 Ордер 3 снимается.
5. **`O3_FILLED`**: при глубоком сквизе налился Ордер 3 (0.786) — бот переносит Take-Profit позиции на общий уровень **0.500 Fib (-0.10%)**. Все 3 ордера закрываются в плюс/БУ.
6. **`AWAITING_SWEEP_CLOSE`**: при срабатывании стопа на 1.000 бот снимает ордера своего слоя и дожидается закрытия часовой свечи:
   - Если свеча закрылась **выше 1.000** (`close >= 1.000`) и закол $\le 0.5\%$ с разворотом MACD $\to$ вход в **Вариант 1 (Sweep Reclaim)**.
   - Если свеча закрылась **ниже 1.000** (`close < 1.000`) или закол $> 0.5\% \to$ выставление **Варианта 3 (Сетка манипуляции 1.414 / 1.618)** со стопом на 2.414 Fib.
7. **`IDLE`**: сделка завершена; на каждом закрытии новой свечи бот автоматически сканирует монеты на наличие новых импульсов соответствующего слоя (Minor $\le 24$ свечей, Major $25..96$ свечей).

## 5. Как запускать и тестировать

### 5.1. Запуск тестов (Unit Tests)
```bash
uv run pytest -v
# Все 173 теста должны проходить со 100% успехом
```

### 5.2. Режим симуляции (Dry-Run сканер)
Сканирует монеты из `config/trade_config.yaml` по обоим слоям без выставления ордеров:
```bash
uv run python scripts/bybit_trader.py --dry-run
```

Переопределение монет через командную строку:
```bash
uv run python scripts/bybit_trader.py --symbols "NEAR,ZEC,SUI" --dry-run
```

### 5.3. Боевой режим (Live Trading)
Запуск торговли на реальном аккаунте Bybit в непрерывном фоновом цикле с параллельным ведением Minor и Major сеток:
```bash
uv run python scripts/bybit_trader.py --live -y
```

Одиночный проход без непрерывного фонового цикла:
```bash
uv run python scripts/bybit_trader.py --live -y --once
```

### 5.4. Проверка подключения и баланса Bybit
```bash
uv run python scripts/test_bybit_connection.py
```
